# D-077 · 자동화 비용 정책 — 봇을 늘려도 돈이 안 들게

**날짜** 2026-07-27 · **상태** 확정 · **관련** D-076(배선 관리) · D-075(예약 무결성)

---

## 1. 왜 이 결정이 필요했나

하루 만에 봇을 2개 늘렸다(`booking-health`·`wiring-check`). 대표님이 물었다:

> "자동으로 계속 체크하면 트래픽 및 서버에 비용이 높아지는 거 아니야?"

**옳은 질문이다.** 자동화는 「공짜로 일해주는 것」처럼 보이지만 실제로는 매번 서버가 돌고, 남의 API 를 부르고, 데이터를 주고받는다. 기준 없이 늘리면 어느 날 청구서로 돌아온다.

그래서 **늘리기 전에 재는 습관**을 규칙으로 굳힌다.

## 3. 그래도 헛일은 안 한다 — SHA 캐시

`wiring-check` 는 창구 73개(951KB)를 받아 훑는다. 매일이면 월 28MB.
큰 돈은 아니지만 **코드가 안 바뀐 날은 받을 이유가 없다.**

→ 마지막 커밋 SHA 를 `api_cache` 에 기억해 뒀다가 **같으면 그냥 끝낸다.**

```
1회차(코드 바뀜) : 창구 73개 훑음 · 6초  · 951KB
2회차(그대로)    : skipped        · 1.2초 · 0KB
```

우리는 코드를 매일 바꾸지 않는다. **실제로 훑는 날은 한 달에 며칠뿐이다.**
`?force=1` 로 강제 실행할 수 있다(검증용).

**이 방식은 다른 봇에도 쓸 수 있다.** 「입력이 그대로면 결과도 그대로」인 일은
입력의 지문(SHA·해시·최종수정일)을 기억해 두고 건너뛴다.

## 4. 규칙 — 새 봇을 만들 때 물어볼 4가지

| # | 물어볼 것 | 기준 | 어긴 예 / 지킨 예 |
|---|---|---|---|
| ① | **바깥 유료 API 를 쓰나** | 쓰면 **쿼터를 코드에 박는다.** 「알아서 조심」은 안 된다 | ✅ `hotel-geo-fill` 하루 135건 상한 |
| ② | **얼마나 자주 도나** | 하루 1회로 될 일을 매시간 돌리지 않는다 | ✅ 두 봇 다 하루 1회 |
| ③ | **바뀐 게 없어도 도나** | 없으면 **건너뛰게 만든다** | ✅ `wiring-check` SHA 캐시 |
| ④ | **조용할 때도 메일 보내나** | **안 보낸다.** 소음이 되면 아무도 안 본다 | ✅ 둘 다 「손댈 게 있을 때만」 |

### 4-1. ①이 가장 중요하다

구글·유튜브 같은 바깥 API 는 **쿼터를 넘기는 순간 돈이 되거나 막힌다.**
막히면 그 봇만 죽는 게 아니라 **같은 한도를 쓰는 다른 기능까지 죽는다.**

> 실제 사례: `hotel-geo-fill` 이 하루 150건이 아니라 **135건**인 이유 —
> 나머지 15건은 **B2B 가입 때 호텔 검색** 몫이다. 봇이 다 써버리면 손님이 가입을 못 한다.

### 4-2. 🔴 절대 건드리면 안 되는 것

- **구글 필드마스크 변경 금지** — Pro 무료(5,000/월)가 Enterprise(1,000·유료)로 추락한다.
- **`hotel-geo-fill` 하루 135건 상한 유지** — 가입 흐름과 한도를 나눠 쓴다.
