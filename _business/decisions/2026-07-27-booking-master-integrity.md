# D-075 · 아고다 예약 업로드 무결성 — 사람이 찾지 않아도 되게

**날짜** 2026-07-27 · **상태** 확정·배포됨

## 왜

대표님 지시:
> "새롭게 아고다 예약 DB를 추가한 곳이 정리가 안 된 것 같아. 매달 새롭게 추가하면 이런 부분이 또 생기면 안 된다.
> 보완책을 찾아. 내가 확인하고 계속 이야기할 수 없잖아. **시스템에서 로직에서 방법을 찾아야 됨.**"

예약을 올릴 때마다 마스터에 없는 호텔이 생겼고, 아무도 모른 채 쌓이다가 화면에서 「(이름 없음)」으로 발견됐다.
**79건 · $13,760 · 67개 호텔.**

## 무엇이 잘못돼 있었나 (api/admin.js 업로드)

| # | 결함 | 결과 |
|---|---|---|
| ① | `hotels` 를 `limit` 없이 읽음 | PostgREST 기본 **1,000줄**에서 잘림. hotels 는 3,185줄 → **2,185개가 매칭 후보에서 아예 빠짐.** 이미 있는 호텔도 「없음」 처리 |
| ② | **이름 글자**로만 매칭 (`includes` 부분포함) | 아고다가 이름을 바꾸면 못 찾음. `agoda_hotel_id` 라는 확실한 열쇠를 안 씀. 게다가 「Hotel A」가 「Hotel A Annex」에 걸리는 오매칭 |
| ③ | 못 찾으면 `hotel_id=null` 로 넣고 **끝** | 알림도 목록도 없음 → 대표님이 화면에서 발견할 때까지 방치 |

## 3중 방어로 바꿨다

### 1차 — 업로드 그 자리에서 (api/admin.js · `5cd480d8`→`48aefa5e`)

1. `hotels` 를 **1,000줄씩 끊어 전부** 읽는다 (「받은 게 전부」라고 믿지 않는다 · 63)
2. 매칭 순서를 바꿨다: **`agoda_hotel_id` → 이름 정확 → 이름 부분(8자 이상만)**
   아고다가 이름을 바꿔도 id 는 안 바뀐다. 짧은 이름 부분매칭은 오매칭을 만들어 막았다.
3. 그래도 못 찾으면 **그 자리에서 마스터에 만든다** (`ensureHotelMaster`).
   예약이 붙었다는 것은 실존 호텔이라는 증거다. 아고다가 이름·나라·도시·성급을 다 줬다.
4. 업로드 응답이 **결과를 말해준다**: `match_stat`·`auto_created`·`unmatched`·`health.truncated_warning`

### 2차 — 매일 도는 그물 (api/cron/booking-health.js · 신설 `f5d191a9`)

매일 KST 09시. 1차를 빠져나간 것을 잡는다.
- 못 붙은 예약을 찾아 **아고다 id 로 이미 마스터에 있으면 이어 붙인다** (놓친 연결 복구)
- 진짜 없으면 **마스터에 등록**하고 예약에 연결
- 손 못 댄 것이 있을 때만 메일. 조용하면 안 보낸다(소음 방지)
- `?dry_run=1` 로 보기만 가능

### 3차 — 표시를 남긴다

자동 등록된 호텔은 `merge_status='auto_from_booking'` 으로 표시된다.
사람이 나중에 성급·유형·지역을 확인하면 된다.

⚠️ `status` 는 CHECK 제약이 있다 — 허용값은
`pending·review·approved·paid·producing·published·rejected·refunded·archived·catalog` 뿐.
`'auto'` 를 넣으려다 67건 전부 실패했다. **자동 등록은 `status='catalog'`, 표시는 `merge_status`.**
`operating_status` 는 모르므로 **비워 둔다.** 지어내지 않는다.
