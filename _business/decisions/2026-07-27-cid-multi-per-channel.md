# D-078 · 아고다 CID — 채널 하나에 번호 여럿

**날짜** 2026-07-27 · **상태** 확정·배포됨 · **관련** D-072(다채널 배포)

## 무슨 일이 있었나

대표님이 호텔이야 원고를 올렸는데 **「확인필요」로 되돌아왔다.**

```
· 고쳐야 할 곳: 모르는 cid 입니다: 1931762
```

그런데 **채널 메뉴에는 그 번호가 멀쩡히 등록돼 있었다** (호텔이야 · approval-2nd).

## 원인 — 두 곳이 서로 다른 곳을 봤다

| 어디 | 무엇을 보나 | 호텔이야 cid 를 몇 개로 아나 |
|---|---|---|
| 채널 메뉴 화면 | `channel_cid_map` (DB) | **3개** — 1932026(new)·1922821(old)·1931762(approval-2nd) |
| 원고 검사 (`api/youtube.js`) | 규격 문서 `_content/youtube/호텔이야.md` | **1개** — 1932026 뿐 |

규격 문서에서 `cid\s*=\s*(\d+)` 정규식으로 **처음 하나만** 뽑아 쓰고 있었다.

**한 채널이 cid 를 여러 개 쓰는 것이 정상이다.** 아고다 승인이 다시 나거나, 웹/유튜브를 나누거나,
옛 번호로 예약이 계속 들어오기 때문이다. 그런데 원고 검사는 그걸 몰랐다.

→ **정상 원고가 매번 되돌아왔다.**

## 고침

`api/youtube.js` 가 **문서 cid + DB 등록 cid 를 합쳐서** 인정한다.

- 문서의 cid = 「대표 cid」 (원고를 새로 만들 때 다는 번호) — 그대로 둔다
- `channel_cid_map` 의 `is_active` cid = **전부 인정** (예약이 실제로 이 번호로 잡힌다)
- DB 를 못 읽어도 문서 cid 로는 돌아간다 (안전판)

### 오류 메시지도 고쳤다

「모르는 cid」만 던지면 어디를 고쳐야 할지 알 수 없다. 이제 단계를 알려준다.

| 상황 | 메시지 |
|---|---|
| DB 에도 없음 | `모르는 cid 입니다: 9999999. **채널 메뉴 › 아고다 CID 에서 이 번호를 먼저 등록**해 주세요.` |
| DB 엔 있는데 규격 .md 가 없는 채널 | `cid … 는 채널 JP 로 등록돼 있지만, 그 채널은 원고 자동생성 **규격(.md)이 없습니다.**` |

## 검증 (2026-07-27)

```
cid=1931762 (approval-2nd) → ✅ 통과
cid=1922821 (old)          → ✅ 통과
cid=1932026 (new)          → ✅ 통과
cid=1946819 (호텔이곳)      → ✅ 통과
cid=9999999 (없는 번호)     → ❌ 안내와 함께 막힘  ← 이게 맞다
```

## 두 번째 버그 — 장부에 «대표 cid» 가 적히고 있었다 (같은 날 발견)

첫 수정으로 원고는 통과했다. 그런데 등록된 줄을 보니:

```
원고 링크 : cid=1931762
장부(publications.cid) : 1932026   ← 뒤바뀜
```

`api/_lib/youtube-render.js` 가 `rule.cid`(규격 문서의 **대표 cid**)를 그대로 저장하고 있었다.

**이게 왜 심각한가**: 아고다 수수료는 **cid 별로** 들어온다.
장부에 다른 번호가 적히면 «이 영상이 어느 번호로 돈을 벌었나»를 영영 못 맞춘다.
**돈의 출처를 장부가 거짓말하는 것**이다.

→ 원고 링크에 실제로 붙은 cid 를 저장하도록 고쳤다(`actualCid`).
   링크에 cid 가 없을 때만 규격의 대표 cid 를 쓴다.

경고도 바꿨다. 전에는 「대표 cid 와 다르면」 경고였는데,
이제는 **「링크 3개끼리 서로 다를 때」**만 경고한다 — 그게 진짜 수수료가 갈리는 경우다.

이미 등록된 `HT-0002` 는 `1931762` 로 바로잡았다.

### 검증
```
원고 cid=1931762 → 장부 1931762 ✅
원고 cid=1932026 → 장부 1932026 ✅
원고 cid=1922821 → 장부 1922821 ✅
```

## 배운 것

**같은 사실을 두 곳에서 따로 관리하면 반드시 어긋난다.**
cid 의 정본은 `channel_cid_map`(DB) 이다. 규격 문서의 cid 는 「새 영상에 다는 대표 번호」일 뿐이다.

`publications.js` 는 처음부터 DB 를 보고 있었다. **`youtube.js` 만 문서를 보고 있었다.**
→ 앞으로 cid·채널 같은 「목록」은 **문서에 적지 말고 DB 에서 읽는다** (54-0V: 목록은 세는 것이지 적는 게 아니다).
