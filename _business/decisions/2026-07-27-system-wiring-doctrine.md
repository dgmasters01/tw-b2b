# D-076 · 시스템 배선 관리 — 「그때그때 다시 확인」을 끝낸다

**날짜** 2026-07-27 · **상태** 확정·배포됨 · **관련** D-074(영문판) · D-075(예약 무결성)

## 1. 왜

대표님 지시:

> "자동화 로봇 및 전체의 세부 시스템, 작동되는 것이 세부적으로 **어떤 것이 연동되어서 작동되고
> 어떤 페이지가 연동되어서 바꿔야 되는지 정리가 안 되어서 그때그때 다시 확인하는 게 문제임.**"
>
> "**gohotelwinners와 스튜디오 페이지도 같이 연동이 되니까. 통합적으로 전체를 체크해서
> 체계적으로 정리해 놓아야 됨. 하나만 하면 또 꼬이겠지.**"

맞다. 실제로 이 문제 때문에 하루에 사고가 3건 났다.

| 사고 | 뿌리 |
|---|---|
| 성급이 5성으로 잘못 표시 (D-074 §4-2-G) | `hotels` 를 1,000줄만 읽음 |
| 예약 79건이 호텔에 안 붙음 (D-075) | **같은 뿌리** — 다른 창구에서 |
| B2B 매니저 목록에 호텔 2,252개 누락 | **또 같은 뿌리** — 이번에 발견 |

**같은 실수를 세 군데서 따로 했다.** 한 곳을 고쳐도 나머지는 그대로였다.
사람이 기억으로 관리할 규모가 아니다 — **화면 25 · 창구 72 · 표 55 · 봇 9 · 문서 296.**

## 2. 무엇이 문제였나 — 「손으로 쓴 지도는 반드시 낡는다」

`SYSTEM_MAP.md` 는 잘 쓰여 있었다. 그런데 거기엔 **크론과 큰 표만** 있었다.
없던 것은 이것이다:

- 이 표를 만지면 **어느 창구**가 깨지나
- 그 창구는 **어느 화면**이 쓰나
- 그 화면은 **B2B 쪽인가 스튜디오 쪽인가** (양쪽이면 둘 다 고쳐야 한다)

그리고 이걸 손으로 적어두면 **코드가 바뀌는 순간 거짓말이 된다.**
거짓말하는 지도는 없느니만 못하다 — 믿고 고쳤다가 다른 곳이 깨진다.

## 3. 답 — 코드에서 뽑는다

**코드가 정답이다.** 코드에서 뽑으면 절대 낡지 않는다.

### 3-1. `_os/tools/wiring-scan.mjs` (신설)

```bash
node _os/tools/wiring-scan.mjs          # SYSTEM_WIRING.md 를 새로 쓴다
node _os/tools/wiring-scan.mjs --check  # 낡았는지만 확인 (종료코드 1)
node _os/tools/wiring-scan.mjs --json   # 기계용
```

무엇을 뽑나:

| # | 뽑는 것 | 어떻게 |
|---|---|---|
| ① | 화면 → 부르는 창구 | HTML 안의 `'/api/...'` |
| ② | 창구 → 만지는 표 (읽기/쓰기 구분) | `.from('t').select/insert/update` · `/rest/v1/t` |
| ③ | 봇 → 도는 시각·만지는 표 | `vercel.json` crons |
| ④ | **표 → 고쳐야 할 곳 (역인덱스)** | ①②③ 을 뒤집는다 |
| ⑤ | 위험 신호 | 1,000줄 잘림 · 아무도 안 부르는 창구 |

### 3-2. `SYSTEM_WIRING.md` (자동 생성 · 손대지 않는다)

핵심은 **§1 역인덱스**다. 표 하나를 찾으면 이렇게 나온다:

```
| bookings_agoda | 읽는 창구 8개 | 쓰는 창구: admin.js · cron/booking-health.js
                 | 영향받는 화면 7개  ⚠️ 관리자 + B2B 매니저 + 공개·가입 + 스튜디오 양쪽
                 | 도는 봇: booking-health |
```

**「양쪽」 경고**가 대표님이 말씀하신 *"하나만 하면 또 꼬이겠지"* 를 막는다.

### 3-3. `_os/tools/table-rows.json` — 위험도 판정

표 행수를 적어두면 스캐너가 위험을 **등급**으로 매긴다.

| 등급 | 뜻 |
|---|---|
| 🔴 이미 넘음 | 표가 1,000줄을 넘었다 — **지금 틀린 답이 나오고 있다** |
| 🟡 곧 넘음 | 500줄 이상 — 곧 터진다 |
| 🟢 여유 | 아직 괜찮지만 표는 자란다 |

행수 갱신:
```sql
select 'hotels' t, count(*) n from hotels union all select 'keyword', count(*) from keyword ...
```
→ 결과를 `_os/tools/table-rows.json` 에 넣는다. **월 1회면 충분하다.**

## 4. 이번에 스캐너가 잡아낸 것

### 4-1. 🔴 실제로 터지고 있던 곳 — `api/admin.js` L95

```js
// B2B 매니저 목록: hotels 를 limit 없이 읽음 → 1,000줄에서 잘림
`/rest/v1/hotels?select=id,user_id,hotel_name,status,...`
```

`hotels` 는 3,252줄. **2,252개 호텔의 담당자가 관리자 화면에 안 보이고 있었다.**
아무도 몰랐다. 고쳤다(끊어 읽기).

### 4-2. 오탐도 잡았다 — 스캐너를 두 번 고쳤다

처음 돌렸을 때 위험 34곳이 나왔는데, 실제로 보니 대부분 안전했다.

| 오탐 | 왜 안전한가 | 스캐너 보완 |
|---|---|---|
| `hotels?user_id=eq.…` | **필터가 있다** → 소량 | PostgREST 필터 문법(`=eq.`·`or=(`) 인식 |
| `hotels?select=id` + `Range: 0-0` | **개수만 센다** → 줄을 안 받는다 | `count=exact` + `Range: 0-0` 예외 |

→ 위험 34곳 → **22곳**, 그중 진짜 터지는 것 **0곳**.

**오탐이 많은 경보는 아무도 안 본다.** 정확도가 도구의 생명이다.

## 5. 신규 호텔 — 등록만으로 끝나면 안 된다

대표님 지시:

> "우리가 소개한 영상에 호텔만 예약하는 게 아님. 그래서 **신규 호텔이 있으면 호텔 리스트를 만들어서
> 내용을 추가해서 저장해 놓아야 됨.**"

D-075 에서 예약 보고 **자동 등록**까지는 됐다(67곳). 하지만 그것으로 끝이 아니다.
자동 등록된 호텔은 아고다가 준 **이름·나라·도시·성급**뿐이다. 지역·좌표·유형·폐업 여부가 비어 있다.

### 이렇게 이어진다 (전부 자동)

```
아고다 예약 업로드
   ↓  마스터에 없으면 그 자리에서 등록          api/admin.js
   ↓  놓친 것은 다음날 09시 봇이 줍는다          cron/booking-health   (D-075)
   ↓  merge_status = 'auto_from_booking' 표시
   ↓  좌표·주소·폐업 채우기 (하루 3회 · 구글)     cron/hotel-geo-fill
   ↓  지역(구·동네) 채우기 (매일 12시 · 무료)     cron/hotel-district-fill
   ↓  폐업 확인 (월요일)                        cron/hotel-closed-check
   ↓  스튜디오 호텔 메뉴 「새로 들어온 호텔」 카드에 뜬다   ← 신설
```

**사람이 할 일은 마지막 하나뿐이다** — 카드를 눌러 성급·유형이 맞는지 훑어보는 것.

### 스튜디오에 카드를 붙였다

호텔 메뉴에 **「새로 들어온 호텔 · 확인 대기」** 카드가 생겼다.
누르면 자동 등록된 호텔만 걸러 보이고, 목록에는 **`신규`/`NEW`** 배지가 붙는다.
(창구가 `auto_new` 를 실어 보낸다 — `api/content-hotels.js`)

## 6. 앞으로의 규칙 (이게 이 문서의 핵심)

### 6-1. 무엇을 고치기 전에

**`SYSTEM_WIRING.md` §1 에서 그 표 이름을 찾는다.** 같이 고쳐야 할 곳이 다 나온다.
「⚠️ 양쪽」이라고 쓰여 있으면 **B2B와 스튜디오를 둘 다** 확인한다.

### 6-2. 작업이 끝나면

```bash
node _os/tools/wiring-scan.mjs
```
을 돌려 `SYSTEM_WIRING.md` 를 **같이 커밋**한다. 창구·화면·봇을 건드렸으면 반드시.

### 6-3. 새 창구를 쓸 때

표를 **통째로 읽지 않는다.** 처음부터 `range(from, from+999)` 로 끊어 읽는다.
지금 표가 작아도 표는 자란다. 「받은 게 전부」라고 믿지 않는다(헌법 63).

### 6-4. 창구는 원본을 보낸다

라벨을 서버에서 한글로 굳혀 보내지 않는다. 원본 코드(`country_en`·`type_code`)를 같이 보내고,
어떤 말로 쓸지는 **화면이 정한다.** (D-074 §4-2-H)

### 6-5. 문서 지도 (SYSTEM_MAP §7 갱신)

| 무엇 | 어디 | 누가 쓰나 |
|---|---|---|
| **배선 사실**(무엇이 무엇과 연결) | **`SYSTEM_WIRING.md`** | **스캐너가 자동** — 손대지 않는다 |
| 시스템 설명·판단·비용 | `SYSTEM_MAP.md` | 사람 |
| 결정 전문 | `_business/decisions/` | 사람 |

**사실은 기계가, 판단은 사람이.** 섞으면 둘 다 낡는다.

정직하게, 처음 답은 **"아직 아니다"** 였다.
`wiring-scan.mjs` 를 만들었지만 **사람이 손으로 돌려야** 했다. 안 돌리면 배선도가 낡고, 낡으면 오늘과 똑같은 사고가 난다.
**도구를 만든 것으로 끝났다고 착각하면 안 된다.**

### `api/cron/wiring-check.js` (신설) — 서버가 매일 스스로 돌린다

레포에 커밋하지는 않는다(권한 밖). **알리기만 한다.** 고치는 것은 사람이 한다.

## 7. 한계 (정직하게)

- 스캐너는 **정적 분석**이다. 변수로 만든 테이블 이름(`` sb.from(`${t}`) ``)은 못 잡는다.
  지금 코드엔 그런 것이 없지만, 앞으로 쓰지 않는 것이 좋다.
- `table-rows.json` 은 손으로 갱신한다. 자동화할 수 있지만 **스캐너가 DB 없이 돌아야** 하기에 뺐다.
- 화면 → 창구는 `'/api/...'` 문자열로 찾는다. 주소를 조립해서 부르면 못 잡는다.

### 아직 «못» 막는 것 — 다음 과제

| 무엇 | 왜 못 잡나 | 언제 티가 나나 |
|---|---|---|
| 화면 렌더 버그 (`t is not a function`) | 스캐너는 **DB 배선**만 본다. 화면 안쪽 로직은 안 본다 | 사람이 그 화면을 열 때 |
| 영어 화면 미번역 | 전수 스캔 도구는 있으나 **수동**이다 | 직원이 볼 때 |
| 값 자체가 틀린 것 (호텔 이름 뒤바뀜) | 코드는 멀쩡하고 **데이터가 틀린** 경우다 | `publications` 저장 시 대조 경고를 넣어 일부만 막힘 (D-074) |

**이 셋은 아직 대표님이 발견하실 수 있다.** 다음에 하나씩 봇으로 옮긴다.
우선순위: ① 화면 렌더 오류 자동 감지 → ② 미번역 자동 점검 → ③ 값 대조 확대.
