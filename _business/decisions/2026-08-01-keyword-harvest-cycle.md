# D-075 · 키워드 조사 시스템 — 발굴 규칙과 순환 구조 바로잡기

**날짜**: 2026-08-01
**결정자**: 이지형 대표님
**상태**: 확정 · 배포 완료
**관련 파일**: `api/kw-survey-now.js`, `api/cron/kw-survey.js`, `api/content-keywords.js`, `studio.html`

## 왜 다시 손댔나

대표님이 삿포로 화면을 보시고 세 가지를 짚으셨다. 셋 다 **시스템이 사실과 다르게 돌고 있던 것**이었다.

> *"여행 조사 때 자유여행 키워드도 있잖아. 여행의 가장 큰 키워드는 여행, 자유여행이잖아."*
> *"한국은 띄어쓰기 붙여쓰기에 따라 달라지잖아."*
> *"한 달 안에 모든 도시 가능하다고 했는데 정상적으로 하고 있는 거 맞아?"*

---

## 1. 발굴이 「자유여행」을 아예 안 캐고 있었다

### 무엇이 잘못됐나

씨앗(발굴 출발점)이 **세 개뿐**이었다.

```
호텔 · 숙소 · 여행
```

「자유여행」은 씨앗에 없었다. 자동완성이 우연히 물어오면 들어오고, 아니면 없었다.

거기에 **여행 축 상한이 8개**였다. 삿포로 화면에 여행 검색어가 정확히 8개만 뜬 이유다 — 9번째부터는 **잘려 나갔다**. 실제로 우리 DB 전체에서 여행 축은 도시마다 최대 9개뿐이었다.

### 어떻게 고쳤나

| 항목 | 전 | 후 |
|---|---|---|
| 씨앗 | 호텔·숙소·여행 | 호텔·숙소·여행·**자유여행** |
| 여행 축 상한 | 8개 | **16개** |
| 숙박 축 상한 | 28개 | 24개 |
| 품질 기준(여행) | 1개 이상 | **2개 이상** |

여행은 수요가 큰 축이다. 숙박이 주력이라는 원칙은 유지하되, 여행을 8개로 조르던 건 근거가 없었다.

## 2. 띄어쓰기 짝이 숙박에만 붙어 있었다

한국말은 붙여 쓰느냐 띄어 쓰느냐로 검색량이 달라진다. 「삿포로 호텔」과 「삿포로호텔」은 다른 검색어다.

그런데 붙여쓰기 씨앗이 **숙박 두 개뿐**이었다.

```
삿포로호텔 · 삿포로숙소       ← 여행이 없다
```

그래서 「삿포로여행」·「삿포로자유여행」은 한 번도 재본 적이 없다. 화면에 「삿포로호텔」 붙임말은 보이는데 여행 쪽 붙임말은 없던 이유다.

**고침**: 붙여쓰기 씨앗에 `도시여행`·`도시자유여행`을 넣었다.

같이 한 일 — 붙여쓰기 후보는 「있는지 확인」만 하면 되는데 자모 발굴(15회 호출)까지 돌리고 있었다. **자동완성 1회**로 줄였다. 총 호출이 **75회 → 64회**로 줄어 구글 차단(429) 위험도 낮아졌다.

## 3. 🔴 봇이 새 도시를 영영 안 늘리는 구조였다

가장 큰 문제다.

### 무엇이 잘못됐나

순환이 이렇게 짜여 있었다.

```
① 이번 달에 안 끝난 도시를 전부 재조사한다
② ①이 다 끝나면 → 새 도시를 발굴한다
```

**달이 바뀌는 순간 기존 도시 전부가 ①로 들어간다.** 8월 1일 기준 재조사 대기가 **79곳**이었다. 봇은 하루 2~3곳을 처리한다. 즉 **8월 한 달을 통째로 재조사에 쓰고, 새 도시는 한 곳도 안 늘어난다.**

실측:

| 항목 | 수 |
|---|---|
| 예약이 있는 도시 | **145곳** |
| 검색어가 발굴된 도시 | **81곳** |
| **한 번도 손 안 댄 도시** | **64곳** |
| 8월 재조사 대기 | 79곳 |
| 발굴 실패로 건너뛰기 등록 | 15곳 |

### 어떻게 고쳤나

**3회에 1번은 새 도시 발굴을 먼저 한다.** 봇은 2시간마다 도니 하루 12회차 중 **4회가 개척**에 쓰인다.

```js
const NEW_EVERY = 3;   // 3=균형 · 2=개척 우선 · 5=재조사 우선
```

비율을 바꾸려면 이 한 줄만 고치면 된다.

두 가지 안전장치를 같이 뒀다.
- **대표님이 직접 고른 도시(`harvest-now`)는 항상 새치기** — 발굴 차례라도 양보하지 않는다.
- **발굴할 새 도시가 없으면 재조사로 돌아간다** — 예전엔 그냥 쉬어버렸다.

## 4. 끝난 조사를 「예약 중」이라 말하고 결과를 감췄다

삿포로는 7월 27일에 조사가 끝났는데(`status=done`) 화면은 "봇이 채우는 중"이라 하고 결과를 안 보여줬다.

원인은 창구 한 줄. **이번 달 기록만** 보고 없으면 무조건 「채우는 중」을 돌려줬다. 삿포로는 7월에 끝냈고 8월 재조사는 아직 안 왔으니 「없음」이 된 것이다.

**원칙을 세웠다** — *지난달에라도 끝낸 조사가 있으면 그건 끝난 것이다. 재조사 대기일 뿐이다.*

이 한 줄로 **25곳**이 잘못된 「채우는 중」에서 제자리를 찾았다.

## 지금 남은 것 (다음에 할 일)

### ① 도시 이름 때문에 못 캐는 곳 15군데

자동완성이 이름을 못 알아들어 발굴에 실패했고, 건너뛰기 목록에 들어가 **영영 조사되지 않는다.**

```
오키나와 본섬 · 지바 / 치바 · 푸꾸옥 섬 · 씨엠림 / 시엠립 · 몰디브 아일랜드
꼬피피 / 코피피 · 누와라 엘리야 · 롬복 · 부르고스 · 치앙라이 · 퀸스타운
판티엣 · 하롱 · 후지카와구치코 · 우키하
```

이름에 슬래시·군더더기(「본섬」·「아일랜드」·「섬」)가 붙어 검색이 안 되는 경우가 대부분이다. 이름을 다듬으면 살아난다.

### ② 이미 조사된 81곳은 옛 규칙으로 캐졌다

「자유여행」과 여행 붙임말은 **이번 수정 이후에 조사되는 도시부터** 들어간다. 기존 도시는 다음 재조사 때 자연히 채워지지만, 급한 도시는 대표님이 [＋ 조사 추가]로 다시 넣으면 바로 반영된다.

---

## 안 하기로 한 것

- **모든 도시를 한꺼번에 다시 조사하지 않는다.** 구글 차단(429)을 부른다. 봇 순환에 맡긴다.
- **검색어 상한을 무한정 늘리지 않는다.** 도시당 40개 안팎이 트렌드 호출 10회에 맞는 크기다.
- **띄어쓰기 조합을 기계적으로 다 만들지 않는다.** 자동완성에 실제로 살아 있는 형태만 넣는다 — 없는 검색어를 지어내면 숫자가 거짓이 된다.
