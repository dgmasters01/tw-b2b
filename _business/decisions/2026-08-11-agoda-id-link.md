# 스튜디오 호텔 ↔ 아고다 번호 잇기 (2026-08-11)

> **왜**: 유튜브·블로그가 소개한 호텔이 우리 영업 명단의 어느 곳인지 알아야
> ① $200 상품의 「노출했다」 증명 ② 아고다 수수료의 호텔별 귀속 ③ 블로그↔스튜디오 통합 보고가 된다.
> **상위 규범**: D-071 §2-A (잣대 순서) · HOTEL_MATCH.md 원칙② · DATA-BOUNDARY.md

## 0. 🔴 이번에 바로잡은 것 — 잣대 순서

어제 세운 계획은 **거리(좌표)를 1순위**로 쓰고 있었다. D-071 §2-A 위반이다.
대표님 지적(*"사업자등록번호 같은 걸 확인하면 되지 않나? 한 건물에 여러 호텔이 많다"*)으로 원문을 다시 읽고 되돌렸다.

```
1순위  아고다 원본 물증 (예약에 찍힌 번호 · 리뷰 수 · 주소 층)
2순위  이름 · 유형
3순위  거리(좌표)
```

## 1. 🔴 발견 — 번호를 이미 갖고 있었다

미연결 1,247곳 중 **1,243곳의 `agoda_hotel_ids`(예약 파일에서 쌓인 번호 보관함)에 번호가 있었다.**
대표 칸 `agoda_hotel_id` 로만 안 옮겨져 있었을 뿐. 좌표로 추측할 일이 아니었다.

- 아고다 번호 = 아고다가 **판매 계정마다** 주는 번호 → 사업자등록번호 역할
- 아고다 파일에는 사업자등록번호 칸이 **없다**(hotel_master 23칸 실측)
