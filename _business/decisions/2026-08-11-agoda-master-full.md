## 4. 무중단 적재 방법 (9시간 · 서버 안 죽음)

🔴 2026-07-22 에 대량 적재로 DB가 뻗어 로그인까지 멈춘 이력이 있다. 이번엔 다음으로 막았다.

```
① 새 표에 넣는다              지금 쓰는 표는 손도 안 댐 → 서비스 영향 0
② 매 묶음마다 두 사이트 응답 측정
     4초 초과 → 쉬고 재확인 → 회복되면 계속
     두 번 연속 이상 → 정지
③ 창구 두 문을 번갈아          스튜디오 90회 / 블로그 90회 (차선 분리 덕분)
④ 다 넣고 검증 → 이름 바꿔치기(1초)
⑤ 옛 표는 hotel_master_old_20260811 로 보관
```

### 실전에서 배운 것
- **묶음이 클수록 서버가 편하다.** 4,000행 배치일 때 응답 0.07초. 문을 자주 여닫는 게 부담.
- 그래도 **긴 소개글이 몰린 구간**(CSV 216만~222만 부근)은 500~800행으로 줄여야 통과.
- 503/502 로 **8개 구간이 통째로 빠졌다.** 총량만 보면 못 잡는다 → **id 대조로 구멍을 찾아야 한다.**
- 마지막 1건은 주소에 **널 문자(\x00)** 가 있어 실패. 걷어내고 삽입.
