# 창구 차선 분리 (2026-08-11) — 동시 개발이 가능해진 지점

> **대표님(2026-08-11)**: *"나는 개발이 동시에 해도 문제가 없는 시스템을 만들고 싶었다."*
> **상위 규범**: DATA-BOUNDARY.md · staycurate `HANDOVER.md §4`(창구 목록)

## 1. 무엇이 문제였나

창구(`/api/ops/*`)가 전부 gohotelwinners 에 있고, `db-query` 한도가 **카운터 하나**였다.

```
스튜디오 창이 90회를 쓰면  →  블로그 창은 그 시간 내내 문이 안 열림
```
2026-08-11 오전 실측: 아고다 번호 연결 작업이 한 시간에 90회 이상 사용.
같은 시간 블로그 창이 돌았다면 멈췄다.

## 2. 고친 방식 — 차선을 나눈다 (환경변수 0 · 대표님 손 0)

| | 전 | 후 |
|---|---|---|
| 전체 한도 | 120/시간 | **120/시간 (그대로)** — DB 보호선 |
| 한 사업 상한 | 없음(독식 가능) | **90/시간** |
| 상대 몫 | 0 가능 | **최소 30 보장** |

호출 시 헤더 하나를 붙인다.
```
x-ops-client: studio | blog | package | personal      (없으면 studio)
```

🔴 **전체 한도를 올리지 않았다.** 2026-07-22 에 600 으로 올렸다가 DB가 뻗은 이력이 있다.
   부하는 그대로 두고 «독식만» 막는 것이 핵심.
⚠️ 이건 차선 나누기이지 인증이 아니다. 인증은 `x-ops-token` 이 이미 한다.

## 3. 블로그 쪽에서 할 일 (한 줄)

블로그가 `db-query` 를 부를 때 헤더에 `x-ops-client: blog` 를 추가한다.
안 붙여도 동작하지만, 붙여야 스튜디오와 차선이 갈린다.

## 4. 검증 (2026-08-11)
```
미지정 → studio  client_used 1/90 · total 1/120
blog             client_used 1/90 · total 2/120
package          client_used 1/90 · total 3/120
```

## 5. 아직 안 된 것 — 2단계 (대표님 5분 필요)

지금은 **한도**만 갈렸고, **문 자체**는 여전히 gohotelwinners 에 하나다.
→ gohotelwinners 가 죽으면 블로그 발행·적재가 멈춘다(사이트 열람은 정상).

**진짜 분리 조건**: staycurate Vercel 프로젝트에 환경변수 2개 추가
```
SUPABASE_ACCESS_TOKEN   (gohotelwinners 프로젝트에 있는 값과 동일)
CLAUDE_OPS_TOKEN        (이미 있음 — 확인만)
```
넣으면 staycurate.com/api/ops/db-query 를 만들어 완전 독립시킨다.
Claude 는 Vercel 환경변수를 설정할 수 없으므로 이 단계는 대표님이 하셔야 한다.

## 6. 사업이 늘면
`KNOWN_CLIENTS` 에 한 줄 추가 → 그 사업도 자기 차선 90회를 가진다.
