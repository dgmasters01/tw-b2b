**서비스** 블로그(staycurate) · **관련** GAPS §V(08-29 판정) · §BA

## 무엇이 있었나

> 대표님: *"올스테이는 일부 호텔만 소개하는 거라고 했잖아. 그래서 올스테이 이제 안 쓰기로 하지 않았나?"*
> *"올스테이 경우 내용이 별로 없을 것 같아. 공식 홈페이지를 찾고 다른 방법을 찾는 게 맞지 않나?"*

🔴 **대표님 기억이 정확했다.** GAPS §V(2026-08-29)에 이미 확정돼 있었다.
> allstay 는 「있으면 좋은 보너스」로 두고, **소개·사실의 주력은 공식 홈페이지**로 한다.

**그런데 코드는 안 고쳤다.** 09-01 까지 allstay 일꾼이 계속 주력처럼 돌고 있었다.

## 실측 (2026-09-01)

```
allstay        90건 →  notfound 73건 (81%) · ok 17건
official_site  49건 →  ok 34건            (이미 두 배 건진다)
```

allstay 는 도시마다 6곳 안팎만 다루는 큐레이션 사이트다(§V 실측: tokyo 6 · osaka 6 · krabi 0).
**글에 쓰는 호텔 546곳 대부분이 애초에 거기 없다.** 그런데도 매일 두드리고 있었다.

## 결정

### ① allstay — 「지운다」가 아니라 「멈춘다」
```
api/bot-intro.js   시계로 부르면 아무것도 안 한다. 손으로 ?force=1 을 붙일 때만 돈다
                   🔴 이미 건진 17건은 살아 있는 자료다 — 지우지 않는다
DB 명부·registry    state='retired' · 은퇴 사유와 실측 숫자를 note 에 남김
```

### ② 공식 홈페이지가 주력
```
vercel.json   /api/bot-official?limit=5   매시 30분 (전용 시계 신설)
              그전에는 cron-collect 가 가끔 부르기만 했다
방법          그 호텔이 공개한 공식 홈페이지 「한 장」만 연다(목록·검색 안 봄)
              페이지에 호텔 이름이 있는지 확인 → 엉뚱한 페이지 저장 방지 · 180일 기한부
```

### ③ 화면에도 반영
「지금 채울 곳」의 「어디서 얼마나」 표를 후기만에서 **후기+소개문+사진**으로 넓혔다.
🔴 **꼬리표로 「왜 0인지」를 못 박았다** — 숫자만 보면 고장으로 오해한다.
```
*  라쿠텐은 일본 호텔만 캡니다 — 해외에서 0은 정상 (D-097)
†  올스테이는 2026-09-01 은퇴 — 소개문 주력은 공식 홈페이지
```

## 🔴 남은 문제 — 대표님 판단이 필요하다

```
글에 쓰는 호텔        546곳
 ├ 공식 주소 있음     199곳  → 아직 안 캔 곳 107곳 (매시 5곳씩 자동, 약 22시간)
 └ 🔴 공식 주소 없음  347곳  → 소개문을 얻을 길이 없다
```
**347곳을 어떻게 할지 의논해야 한다** (구글 검색으로 공식 주소를 찾는 일꾼을 만들까?).

## 🔴 여기서 얻은 규칙

```
① 문서에서 「격하」로 판정한 일꾼은 코드와 시계도 실제로 바꿨는지 확인한다.
   판정만 하고 코드를 안 고치면 아무것도 바뀌지 않는다 — 이번이 그랬다.
② 일꾼을 그만 쓸 때는 「지우기」 전에 「멈추기」를 먼저 본다.
   이미 모은 자료가 쓸모 있으면 일꾼만 멈추고 자료는 남긴다.
③ 화면에 0으로 나오는 칸에는 「0이 정상인지」를 꼬리표로 적는다.
```
