# D-099 · 캡슐호텔·도미토리는 싣지 않는다 — 「남이 준 분류 칸」을 믿지 않는다

**날짜** 2026-09-01 · **카테고리** data · **상태** 확정
**서비스** 블로그(staycurate)
**관련** GAPS §AU

---

## 무엇이 있었나

「9월 4성급 나고야」 6위에 **캡슐호텔(안신 오야도 나고야)**이 들어가 검수까지 올라왔다.
대표님 발견: *"지금 캡슐호텔이나 도미토리 소개하면 안 됨. 나고야 3성급인데 캡슐호텔이야."*

호텔을 고르는 조건에 걸러개가 **이것 하나뿐**이었다.
```sql
and coalesce(m.lodging_type,'hotel') <> 'shared'
```

## 🔴 왜 안 걸러졌나 — 세 겹의 원인

**① 그 칸이 사실상 비어 있다** (실측 2026-09-01)
```
None   2,988,378곳  ← 99%
hotel     23,724곳
shared       433곳  ← 이것만 걸러졌다
```

**② `coalesce(...,'hotel')` 이라 빈칸이면 전부 「호텔」로 통과**한다. 걸러개가 「거르는 척」만 했다.

**③ 아고다 자료 자체가 틀렸다.** 「안신 오야도 나고야」를 `star_rating 4.0 · lodging_type hotel` 로 준다.
같은 체인 도쿄 지점들은 1.0~1.5성이다.

## 결정

### ① 캡슐·도미토리·호스텔·게스트하우스는 싣지 않는다
우리 글은 **호텔·리조트 추천**이다. 잠자리만 파는 숙소는 성격이 다르다.

### ② 이름으로 거른다 — 두 겹으로
```
① 뽑을 때   api/bot-post.js 후보 조건
② 내보낼 때 api/bot-check.js C2 검사
   🔴 ① 만으로는 «이미 글에 들어간 것» 을 못 막는다. 이번이 실제로 그랬다.

거르는 말:
  영문  capsule · anshin oyado · hostel · dormitory · aeropod · nine hours · guest house · guesthouse
  한글  캡슐 · 호스텔 · 도미토리 · 게스트하우스 · 오야도
```
실측 검증: 3성급 이상·평점 8+ 후보에서 걸리는 곳을 표본 확인 → **전부 실제 캡슐·호스텔·게스트하우스(오탐 0)**.
「호텔 앤 호스텔」처럼 겸업하는 곳도 도미토리를 팔므로 제외가 맞다.

### ③ 🔴 「남이 준 분류 칸」을 걸러개로 쓰기 전에 채워져 있는지 먼저 센다
```
select 그칸, count(*) from 표 group by 1
→ 대부분이 null 이면 그 칸으로는 거를 수 없다. 다른 근거(이름·주소·후기)를 찾는다.
```
`lodging_type` 은 99%가 비어 있었다. **비어 있는 칸으로 거르면 「거르는 척」만 한다.**

### ④ 아고다 star_rating·lodging_type 은 「참고」다
캡슐이 4성급으로 오는 일이 실제로 있다. 같은 체인 다른 지점 값과 크게 다르면 의심한다.

## 조치 (2026-09-01 완료)

이미 들어간 5곳을 각 글의 **예비 호텔**로 교체했다 (전부 발행 전 — 독자 노출 없음).

🔴 **교체는 「자리를 맞바꾼다」** — `blog_post_hotel` 에 unique `(post_id, agoda_hotel_id)` 가 있어
「본문 호텔을 예비 id 로 바꾸기」는 중복 위반으로 실패한다(두 번 시도해 두 번 다 실패했다).
```sql
update blog_post_hotel t set
  rank_in_post = case when t.agoda_hotel_id = <캡슐> then <예비순위> else <본문순위> end,
  is_backup    = case when t.agoda_hotel_id = <캡슐> then true else false end
where t.post_id = <글> and t.agoda_hotel_id in (<캡슐>, <예비>)
```

## 🔴 보강 (2026-09-01 저녁) — «방 하나 파는 곳»도 싣지 않는다

> 대표님: *"이미지를 보니깐 완전 민박의 이미지야."* ·
> *"홀리데이 인 익스프레스 … 바이 IHG 이런 곳은 호텔 이름이 아니잖아. 호텔 이름이 없는 곳이 많을 것 같은데."*

### 발견
«5성급 호텔 추천» 글의 **1위가 «마닐라 베이의 프라이빗 하우스 (26m², 침실 1개)»** 였다. 같은 문제 4곳이 전부 1~3위.

### 🔴 «이름에 hotel 이 있나»로 가리면 안 된다
내가 그 안을 냈는데 **대표님이 반례를 들어 반박하셨고 실측이 맞았다.**
```
글에 쓴 호텔 539곳 → 이름에 hotel 없음 213곳
  그랜드 닛코 도쿄 베이 마이하마 (후기 11,029) · 더블트리 바이 힐튼 (11,784)
  홀리데이 인 익스프레스 … 바이 IHG · 베이 스위트 프리미어 스위트  ← 대표님 지적, 둘 다 진짜 호텔
```

### 옳은 기준 — 아고다가 붙인 «방 표기»
방 하나를 파는 곳은 이름이 «○○의 아파트먼트 (26m², 침실 1개, 프라이빗 욕실 1개)» 꼴로 온다.
사람이 지은 호텔 이름에는 그런 표기가 없다.
```
막는 것  m² · 침실 N개 · 프라이빗 욕실 · «의 아파트먼트/스튜디오/하우스/빌라/콘도/방갈로»
        pool villa · homestay (영문)
```
**실측 오탐 0** — 후기 1,000건 넘는 호텔 18,070곳 중 13곳만 걸렸고 전부 진짜 아파트였다.

### 🔴 여기서 얻은 규칙
```
① «이름에 무엇이 들어 있나»로 종류를 가리기 전에 반례를 찾아본다
② 아고다가 «자동으로 붙인 이름»에 답이 있다 — 방 크기·침실 수가 들어오면 방 하나 파는 곳이다
③ 거르개는 «막아야 할 것»과 «통과해야 할 것»을 둘 다 시험하고 배포한다
```

> 대표님: *"여기에도 호텔이 아니고 여관 또는 게스트 하우스도 있는 것 같은데 다시 확인해봐."*

```

          민박 · 모텔 · 펜션 · 게스트하우스 · 비앤비 · 민숙
```

전체 명부 오탐 확인: 후기 1,000건 넘는 곳 중 걸리는 167곳을 표본 확인, 전부 진짜 민박·모텔.

### 🔴 정본 위치

자격(평점 8+·후기 400+) · 빼는 것 세 갈래 · 남기는 것 · 거르개 만들 때 4규칙 · 실제 사고 6건.
