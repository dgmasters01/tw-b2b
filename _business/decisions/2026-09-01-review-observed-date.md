# D-100 · 후기의 「다녀온 시기」를 정하는 법 — 모를 때는 추정하되 표시한다

**날짜** 2026-09-01 · **카테고리** data · **상태** 확정
**서비스** 블로그(staycurate)
**관련** DATA §8(날짜 3개로 나눈다) · GAPS §AY

---

## 무엇이 있었나

대표님: *"아고다의 경우 날짜는 못 가져오는 거야?"*

실측: **아고다는 날짜를 준다.** 우리가 `observed_at` 에 안 넣고 있었다.
```
checkInDate              2026-07-31   실제 다녀온 날
checkInDateMonthAndYear  July 2026
reviewDate               2026-08-05   후기 올라온 날
```
그런데 우리는 `posted_at`·`stay_month` 에만 넣고 `observed_at` 을 비워뒀다.
「12개월 이내」 판정은 `observed_at` 으로 하므로 **아고다 4,157건 · 라쿠텐 1,284건이 통째로 버려지고 있었다.**

## 🔴 그렇다고 「올라온 날」을 그대로 쓰면 안 된다

대표님: *"이전까지 받은 날짜가 없는 것은 그냥 쓰고, 지금부터 받는 건 정상적으로 받으면 문제가 되나?"*

**문제가 된다. 실측 근거:**
```
아고다   묵고 나서 평균 35일 뒤에 후기를 쓴다 · 🔴 최대 1,065일(3년)
```
**3년 전에 묵고 어제 후기를 쓴 사람이 실제로 있다.**
「올라온 날」만 보면 그 후기가 최신으로 둔갑한다. DATA §8 이 정확히 이 함정을 막으려던 규칙이다.

> 2026년 8월에 올라온 글인데 / 내용은 2023년 투숙기 → **사용 금지**

또한 두 칸은 **뜻이 다르므로 복사하면 안 된다.** 실측: 자란 96건 전부 값이 다르고(투숙 5월·수집 8월), 야놀자도 176건 중 151건이 다르다.

## 결정 — 세 갈래 (대표님 A안 확정)

```
투숙 시기를 «안다»        → observed_at 에 그대로. 신뢰 1.0
투숙 시기를 «모른다»
  ① 올라온 날 1년 이내    → observed_at = 올라온 날. 🔴 추정값 표시 + 신뢰 0.8
  ② 올라온 날 1~2년       → 같은 방식. 신뢰 0.5 (출처 2곳 규칙이 알아서 거른다)
  ③ 올라온 날 2년 초과    → 쓰지 않는다. 저장도 하지 않는다
  ④ 날짜가 전혀 없음      → 쓰지 않는다 (DATA §8 규칙 4)
```

**추정값 표시**: `retention_rule = 'observed_estimated_from_posted'`
→ 나중에 「이건 정확한 투숙일이 아니다」를 반드시 구분할 수 있어야 한다.

## 조치 (2026-09-01 완료)

**① 이미 쌓인 것**
```
아고다  2,830건  stay_month «July 2026» → 2026-07-01   (정확한 투숙 달)
라쿠텐  1,190건  stay_month «2026-06»   → 2026-06-01   (정확한 투숙 달)
추정값  1,472건  올라온 날로 대신 + 표시 + 신뢰 하향
제외      227건  2년 초과 · 날짜 전무
```
**② 앞으로**: `bot-agoda-review`·`bot-rakuten-review` 가 `observed_at` 을 함께 넣는다.
아고다는 `checkInDate` 우선 → 없으면 `checkInDateMonthAndYear` 의 1일 → 그것도 없으면 위 세 갈래.

**③ 검증**: 실제 수집 33건 → 전부 날짜 있음 · 추정값 14건은 신뢰 0.8/0.5 · 평균 0.89

## 결과
```
날짜 있는 후기        3,429건(38%) → 8,959건(99.7%)
쓸 수 있는 후기(12개월)              7,472건
```

## 🔴 다음 클로드에게
```
① 후기를 저장하는 일꾼을 새로 만들면 observed_at 을 반드시 채운다.
   못 채우면 그 후기는 «없는 것»과 같다 — 판정이 observed_at 으로만 이뤄진다.
② «올라온 날»과 «다녀온 날»을 같은 것으로 취급하지 않는다.
   실측으로 최대 3년 차이가 났다.
③ 추정으로 채웠으면 retention_rule 에 표시하고 trust_weight 를 낮춘다.
   표시 없이 채우면 «정확한 자료»와 구분이 안 돼 나중에 되돌릴 수 없다.
```
