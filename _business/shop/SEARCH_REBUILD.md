## 만드는 순서

### 1) 창고 — 검색 전용 표를 만든다 (§42-①)

`shop_hotel_search` — 호텔 하나당 한 줄. **무거운 뷰(`v_shop_card`)를 검색이 부르지 않게 하는 것이 목적이다.**

| 칸 | 무엇 |
|---|---|
| `agoda_hotel_id` | 열쇠 |
| `name_ko` · `name_en` | 보여줄 이름 (그대로) |
| `key_ko` · `key_en` | 🔴 **정규화 열쇠** — 소문자 · 띄어쓰기·`-`·`.`·`,`·`&` 제거 |
| `key_city` | 도시·나라를 한글·영어 모두 정규화해 이어붙임 |
| `star_rating` · `city_slug` · `country_slug` | 기존 조건(성급·도시)에 쓴다 |
| `review_count` · `low_price` · `photo_url` | 동점일 때 순서·화면 표시 |

🔴 **`unaccent` 를 쓰지 말고 «직접 지운다»** — 확장에 기대면 나중에 창고를 옮길 때 깨진다.
🔴 **학습 일꾼(`api/cron/learn.js`, 한국시간 01:30)이 매일 다시 만든다.** 새 호텔이 들어오면 따라온다.

### 2) 창고 — 색인 (§42-②)

```sql
create extension if not exists pg_trgm;
create index on shop_hotel_search using gin (key_ko gin_trgm_ops);
create index on shop_hotel_search using gin (key_en gin_trgm_ops);
create index on shop_hotel_search using gin (key_city gin_trgm_ops);
```
🔴 **이것이 있어야 `ilike '%말%'` 이 색인을 탄다.** 없으면 전체를 훑어 느리다.

### 3) 창고 — 점수 함수 (§41-3층)

`search_hotels(q text, p_city text, p_country text, p_star int, p_limit int)`

**들어오면 먼저 «고르게 만든다»** — 소문자 · 띄어쓰기·기호 제거 → `qk`

**점수** (`key_ko`·`key_en`·`key_city` 각각 재서 **가장 높은 것**을 채택)

| 등급 | 점수 | 판정 |
|---|---|---|
| 완전히 같다 | **100** | `key = qk` |
| 그 말로 시작 | **80** | `key like qk || '%'` |
| 모든 말이 다 들어 있다 | **60** | 손님 말을 쪼개 **전부** `key` 안에 있다 |
| 일부만 | **30** | 일부만 있다 |
| 비슷하다 | **10~25** | `similarity(key, qk)` × 25 |

🔴 **「모든 말이 다」가 핵심이다.** 지금 코드는 `rest[0]` 하나만 써서 「센트럴」·「danang」을 버렸다.
🔴 **한글로 치든 영어로 치든 «같은 점수판»을 쓴다.** 어느 쪽으로 쳤느냐로 1등이 달라지면 안 된다.

**정렬** — `점수 desc → review_count desc → low_price asc`
🔴 **점수를 «먼저» 본다.** 지금은 소개 날짜·값 순이라 정확히 맞은 것이 21번째로 밀렸다.

### 4) 창구 — `api/search.js` 를 바꾼다 (§42-③)

- 🔴 **창고를 «한 번»만 부른다** — `rpc/search_hotels`. 지금 6번을 1번으로
- 기존 파싱(예산·성급·도시·풀빌라)은 **그대로 살린다** — 「일본 10만원 3성급」이 계속 되어야 한다
- 🔴 **응답 모양을 바꾸지 마라** — `introduced`·`fresh` 를 그대로 준다. 바꾸면 화면 3곳(`search.html`·시트·첫 화면)이 함께 깨진다
- 캐시: `s-maxage=60`

### 5) 화면 (창구가 빨라진 «뒤»에)

- `shop.js` `sheetType` 의 타자 멈춤 **350ms → 150ms**
- 기다리는 표시를 남긴다 (지금 「호텔을 찾는 중…」이 있다 — 유지)
- 🔴 순번(`SHEET_SEQ`)은 **그대로 둔다** — 늦게 온 옛 답이 새 답을 덮는 것을 막는다

### 6) 2차 (1차를 확인한 «뒤에» 한다)

초성 검색(`ㅅㄹㅅㅌㅇ`) · 한/영 자판 뒤바뀜(`rmfosem`) · 오타 교정(「혹시 이것을 찾으셨나요?」).
🔴 **1차와 함께 넣지 마라.** 한꺼번에 넣으면 무엇이 틀렸는지 못 가린다.

## 🔴 지키기

- 💰 **돈 드는 것을 쓰지 않는다** — Algolia·Elasticsearch 금지. 창고 안에서 끝낸다
- 🔴 **대상을 넓히지 않는다** — 우리가 소개한 호텔 + 신상만. 아고다 명부 전체(23,050곳)를 넣으면
  값을 재지 않는 호텔이 섞여 「가장 싼 날을 찾아 드립니다」가 깨진다
- 🔴 **올리기 전에 `npm run check`** — 오늘 이것이 화면 전체가 하얗게 되는 것을 두 번 막았다
- 🔴 **커밋 «직전»에 「고친 내용이 파일에 있는지」 확인한다**(`grep`) — 오늘 파일 복사가 수정본을 두 번 덮었다
- 🔴 **화면마다 마크업이 다른 곳은 양쪽을 따로 확인한다** — 첫 화면은 시트가 «미리 그려져» 있다(§26)
- 🔴 **되돌리는 법을 `SHOP_ROLLBACK.md` 에 적는다**
