- 손님에게 **아무것도 고르게 하지 않는다**
- 메뉴를 잘 만드는 게 아니라 **메뉴를 없앤다**

### 5-2. 메인 구조 — ✅ **확정 (D-093)**

### 5-3. 「손님이 자기 영상을 찾는 문제」의 답 — **썸네일**
- 손님은 영상을 다시 볼 생각이 없다. 호텔 이름도 기억 못 한다. **기억하는 건 썸네일 그림 하나**
- 그래서 **유튜브에서 본 그 썸네일을, 그 제목 그대로** 맨 위에 건다 → 0.5초 만에 인식
- 카드를 눌러 들어가지 않게, **카드 안에 호텔 3곳과 가격을 이미 펼쳐둔다** → 예약까지 **1번**
- **더 좋은 방법**: 유튜브 설명란 맨 윗줄에 `travelwinners.shop/v/{영상코드}` 전용 주소 → 찾는 단계 **0**. 발행 시 자동 생성, 대표님은 붙여넣기만

### 5-4. 날짜 처리 (중요)
- **숙박 날짜(예: 2025-06-06~08)는 화면에서 제거.** 손님에게 의미 없음
- 대신 **영상 올린 날짜**를 표시 — 손님 기억(「어제 본 거」)과 맞음
- 영상 때 가격은 **작은 회색 기록**으로만: 「영상 때 167,279원」

### 5-5. 가격 표시 (O-4 미확정, 유력안 = 월별 금토일 달력)
- 월 선택(9월/10월/11월) → **금·토·일만 3열 격자**로 날짜별 실제 가격
- 제일 싼 칸 초록 강조, 연휴 칸 빨강 표시
- 칸을 누르면 **그 날짜 그대로 아고다로** → 우리가 보여준 값과 아고다 값이 일치 = 신뢰 유지
- 화면 하단 고지: 「2인 1박 기준 · 오늘 새벽 조회」

## 6. 이벤트 시스템

### 6-1. 카테고리 = **참여 방식**으로 나눔 (경품이 아님)
| 카테고리 | 손님이 하는 일 | 뽑는 방식 |
|---|---|---|
| **추첨형** | 가입·응모 버튼 한 번 | 마감 후 자동 랜덤 |
| **선착순형** | 먼저 누르기 | 순서대로 즉시 지급 |
| **인증형** | 후기·사진·영수증 올리기 | 확인되면 전원 지급 |
| **미션형** | 정해진 행동(구독·댓글·설문) 완료 | 완료자 중 추첨 또는 전원 |
| **초대형** | 친구 데려오기 | 많이 데려온 순 |

**틀 하나로 5종을 다 담는다.** 대표님은 ①카테고리 고르고 ②제목·사진·경품·마감일 넣고 ③시작. 새 이벤트마다 개발 불필요.

### 6-2. 이벤트 페이지 = 여러 이벤트가 동시에 도는 «허브»
- 진행 중 목록 + 끝난 이벤트 당첨자 발표
- **당첨자 발표가 이 페이지의 심장** — 없으면 다음 회차 응모가 죽음
- 이름은 마스킹(김O연), **응모번호는 전부 공개** + 「지급 완료」 표시 + 당첨자 후기
- 누적 당첨 인원·누적 지급액 표시 → 회차가 쌓일수록 강해짐
- **응모번호가 곧 친구 초대 링크** → 광고비 0원으로 회원 증식
- ❌ 응모자 수·당첨 확률은 표시하지 않음(폐기)

### 6-3. 숙박권 이벤트 = B2B와 연결
$200 낸 호텔에게 숙박권을 협찬받으면 **우리 돈 0원으로 가장 센 경품**을 걸 수 있고, 호텔은 「내 호텔이 경품」이라는 홍보를 얻음. gohotelwinners 상품 가치도 올라감.

## 7. 아고다 운영 (기술)

### 7-1. 쿠키 — 🔴 설계에 결정적
- 아고다 제휴 쿠키는 **세션 종료 시 만료(사실상 그 방문 한 번)**. 부킹닷컴 30일·익스피디아 7일과 달리 매우 짧음
- **뜻**: 「오늘 클릭만 시켜두면 나중에 예약하겠지」 = 우리 돈 0원
- **결론**: ① 예약 마음이 든 그 순간에 정확히 아고다로 보낼 것 ② 오늘 안 사는 손님을 다시 부르는 유일한 수단 = **회원 이메일**. 대표님이 회원DB부터 하자고 한 순서가 정확했음

### 7-2. 가격 수집 구조
- 손님 방문 시 실시간 조회 ❌ (한도 90/h로 즉시 막힘, 화면도 3~5초 멈춤)
- **새벽 봇이 미리 수집 → Supabase 저장 → 손님은 저장값을 봄** ✅ 손님 1만 명이 와도 아고다 조회 0번

### 7-3. 조회량 계산 — 🔴 C-12(주말 3칸)로 **1/4로 줄었다**
| 항목 | 옛 계산(한 달 달력) | **새 계산(이번 주말 3일)** |
|---|---|---|
| 호텔 1곳 1회분 | 13일 | **3일** |
| 영상 342편(호텔 1,026곳) | 약 13,300번 | **약 3,078번** |
| 하루 가능량 (90/h × 24h) | 2,160번 | 2,160번 |
| **한 바퀴** | 6~7일 | **1.5일** |

**운영 방침(확정)**
- **전 호텔**: 이번 주말 금·토·일 3일치 — 이틀에 한 바퀴
- **최근·인기 영상 100편(호텔 300곳)**: 매일
- **한 달 달력(13일치)**: 인기 영상 30편에만 — 「다른 날짜 보기」를 실제로 누르는 손님이 보는 것
- **화면은 아고다에 절대 묻지 않는다.** 손님 1만 명이 와도 조회 0번

### 7-4. 비용 — 거의 안 늘어남
| 항목 | 추가 부담 |
|---|---|
| Vercel | 그대로 (저장값만 읽음) |
| Supabase | 약 4만 줄 · 5MB. 이미 301만 건 있어서 무시 가능 |
| 아고다 조회 | 무료 |
| 새벽 봇 | GitHub 무료 한도 안 |

### 7-5. 🔴 먼저 할 일 = 가격 창고 통합
블로그(staycurate)와 이 사이트가 **같은 호텔을 두 번 조회**하고 있음. 창고를 하나로 합치면 한 번만 묻고 둘이 나눠 씀 → **조회 한도가 사실상 2배**. 아고다 허락 불필요, 내부 작업.

### 7-6. CID vs API 키 (혼동 주의)
- **CID** = 「누가 데려왔나」 꼬리표. 100개를 만들어도 조회 한도와 무관
- **API 키** = 가격 물어보는 열쇠. 한도가 걸리는 건 이쪽
- 채널별 키 추가는 가능해 보이나 **한도가 키별인지 계정 전체인지 미확인**, 한도 우회 목적이면 계정 정지 위험. **지금은 요청 안 함(C-10)**

## 9. 참고 — 이 기획에서 나온 «원칙»

- **손님은 글을 안 읽고 화면을 훑는다.** 보여주는 게 전부
- **가격이 올라 있으면 숨기지 않는다.** 숨기면 신뢰가 깨지고 채널 전체가 죽는다. 대신 「그때 얼마였다」를 기록으로 남기고 알림 가입으로 전환
- **순위(Top1/2/3)를 매기면 1위만 크게 하되, 2·3위에 다른 이유를 줘야 클릭이 산다**
- **전체 아고다 개방은 양날의 칼** — 다 열면 「아고다 짝퉁」이 되어 우리 정체성이 사라지고, 알맹이 없는 페이지 수백만 개는 구글 벌점 위험. 반드시 **1층=우리 소개 / 2층=검색 뒷문**으로 층을 나눌 것
- 손님 검색 기록 = **다음 영상 주제 데이터**. 전체 DB 개방의 진짜 값어치는 예약보다 이쪽
