### 🔴 5-B. 짧은 추적 주소 — 규격 정본 (D-117 · 2026-09-06)

```
gohpik.com / {사업} / {코드}          예) gohpik.com/h/cj4bng
              │        └─ 6글자 · 알파벳 abcdefghjkmnpqrstuvwxyz23456789
              │           🔴 0 O 1 I L 을 뺐다 — 전화로 불러주거나 손으로 적을 때 한 글자만 틀려도 링크가 죽는다
              └─ r 스튜디오(기존·건드리지 않음) · h 여행능력자들 · b 블로그 · c CEYLON · p 상품 · e 이벤트
```

**🔴 바꾸지 않는 세 가지**
1. **한 번 정한 사업 글자는 바꾸지 않는다** — 이미 나간 영상 설명란은 고칠 수 없다
2. **코드는 재사용하지 않는다** — 다른 것을 가리키면 과거 통계가 통째로 거짓이 된다
3. **주소에 정보를 붙이지 않는다** — `?src=&v=&won=` 처럼 붙이면 복사하다 잘려 기록이 날아간다. 코드 하나가 창고에서 아홉 가지를 가리킨다(사업·종류·호텔·**주민번호**·상품·숙박일·화면·**채널**·**캠페인**)

**흐르는 길** `gohpik.com/h/{코드}` →(tw-b2b 302) `travelwinners-shop…/s/{코드}` →(해석) `/go/{호텔}?d=&src=&p=&lc={코드}` → 아고다
🔴 **기록은 `/go`·`/pgo` 한 곳에서만 한다.** `/s` 는 넘기기만 한다 — 두 곳에서 기록하면 숫자가 갈라진다.
🔴 **tw-b2b 의 302 는 permanent=false 로 둔다.** 301 로 두면 브라우저가 영구 저장해, `travelwinners.shop` 이 새 프로젝트로 옮겨온 뒤에도 옛 목적지로 간다.
🔴 **도메인 이전 시 할 일**: tw-b2b `vercel.json` 의 `/h/:code` 목적지를 `https://travelwinners.shop/s/:code` 로 한 줄 교체.

**같은 조건이면 같은 코드를 돌려준다**(`api/link.js` 가 먼저 찾아본다) — 같은 링크가 둘이면 통계가 갈라진다.
**봇·프리페치·`?check=1` 은 실적에서 뺀다**(`api/go.js` · 스튜디오 `api/r.js` 규칙 이식). 카톡이 링크를 미리 훑는 것을 세면 공유 100건에 가짜 클릭 100건이 얹힌다.

2026-09-06 실측: 발급 `cj4bng` → 재요청 시 같은 코드(reused) → `gohpik.com/h/cj4bng` → 아고다 9/20~9/21 2인 1박 · CID 1919025 도달 · 클릭 장부에 링크코드·방문자·기기·나라 기록 확인. 기존 `/r` 과 gohotelwinners 무사.

**원인 (코드에서 확인)**

```
실제:    .bar(약 54px) + .wherebar(약 56px) = 약 110px   ← 세부 화면은 「어디 가세요?」 줄이 붙어 두 줄이다
```
🔴 **그래서 이름이 두 번째 줄 뒤에 완전히 가려진 뒤에도 「아직 화면 안에 있다」로 판정**되어 상단바가 비어 있었다. 아주 많이 내려야 겨우 떴다. **두 번 다 「왜 안 되나」가 아니라 「어떻게 되게 하나」로 접근해서 못 잡았다.**

**고친 방법**
- 숫자를 박지 않고 **상단바 실제 높이를 재서 쓴다**(`.stick` 의 `offsetHeight`) — 화면마다 상단바가 한 줄이거나 두 줄이다
- 화면을 돌리거나 폭이 바뀌면 **다시 잰다**
- 🔴 **브라우저 탭 제목은 건드리지 않는다** — 옛 코드는 `setPlace` 를 불러 스크롤할 때마다 **탭 이름이 깜빡였다**

**남은 확인** — 🔴 실제로 스크롤해서 뜨는지는 **대표님 화면에서 눈으로 봐야 한다**(클로드는 브라우저가 없어 IntersectionObserver 동작을 확인할 수 없다). 배포본에 부품이 실린 것까지는 확인했다.

**함께 고친 것** — 없는 주소(`/about` 등)는 화면이 이미 「없는 페이지」를 그리고 있었다(클로드가 앞서 「메인이 뜬다」고 한 것은 **HTML 껍데기만 보고 판단한 오진**). 남은 문제는 **상태 코드가 200이라 구글이 soft 404 로 본다**는 것뿐이라 `noindex` 표시를 붙였다.

## §40 · 2026-09-09 검색 — 왜 정확히 친 이름이 21번째로 밀렸나 (원인·설계)

대표님: *«「그랜드 센트럴 호텔 상하이」라고 검색했는데 첫 번째로 뜨지 않고 21번째로 뜸.

### 🔴 원인 둘 — 코드에서 확정했다

**① 남은 말 중 «첫 단어 하나만» 쓴다** (`api/search.js` — `p.rest[0]`)
```
「그랜드 센트럴 호텔 상하이」
 → 「호텔」이 종류로 빠짐 · 「상하이」가 도시로 빠짐
 → 남은 말 ['그랜드','센트럴']  →  🔴 실제로 찾는 것은 「그랜드」 하나뿐
```
실측: 「그랜드」 포함 **33곳** · 「그랜드+센트럴」 둘 다 **3곳** · 정확히 일치 **1곳**.

**② 정렬에 «일치도»가 아예 없다**
소개 호텔은 `order=published_on.desc`(최신 소개 순), 신상은 `order=low_price.asc`(값 싼 순).
→ **정확히 일치한 1곳이 33곳 사이에서 소개 날짜 순으로 21번째에 놓였다.**

### 업계 기준 — 같은 문제를 겪고 같은 답을 냈다

Traveloka 검색팀 기록: <cite index="1-1">인기도에만 기대면 이름이 특이한 호텔은 아무리 정확히 쳐도 목록 아래로 밀린다. 「hotel j」를 치면 더 인기 있는 「hotel jxxx」가 위에 오고 정작 「hotel j」는 바닥에 남는다. 그래서 질의와 «정확히 일치»하는 항목에 가산점을 준다.</cite>
🔴 **우리 문제와 «똑같다».** 우리는 인기 대신 「소개 날짜」를 썼을 뿐이다.

### 설계 — 점수제로 바꾼다 (아직 안 함 · 대표님 승인 대기)

**1) 모든 단어를 «AND» 로 찾는다** — `rest[0]` 하나가 아니라 남은 말 전부.

**2) 일치 «등급»으로 점수를 준다. 한글·영어 어느 쪽이든 같게 본다.**

| 등급 | 점수 | 보기(「그랜드 센트럴 호텔 상하이」) |
|---|---|---|
| 완전히 같다 | **100** | 그랜드 센트럴 호텔 상하이 |
| 그 말로 시작한다 | **80** | 그랜드 센트럴 호텔 상하이 푸동 |
| 모든 말이 다 들어 있다 | **60** | 상하이 그랜드 센트럴 호텔 |
| 일부만 들어 있다 | **30** | 그랜드 하얏트 |
| 비슷하다(오타) | **10~25** | 그랜센트럴 |

**3) 점수가 같으면** 후기 수 → 값 순. **점수를 먼저 본다 — 이것이 핵심이다.**

**4) 만드는 법** — 창고에 «점수 매기는 함수»를 두고 창구가 그것을 부른다.
지금처럼 `ilike` 를 이어 붙이는 방식으로는 **점수를 매길 수 없다**(PostgREST 로 계산 정렬이 안 된다).
- `pg_trgm`·`unaccent` 확장은 **아직 안 켜져 있지만 켤 수 있다**(실측). 오타 허용에 쓴다
- 🔴 **돈이 들지 않는다** — 창고 안에서 끝난다. 외부 검색 서비스(Algolia 등)를 쓰지 않는다

**5) 대상** — 지금처럼 **우리가 소개한 호텔 + 신상**만 본다.
아고다 명부 전체(23,050곳)로 넓히지 않는다 — 값을 재지 않는 호텔이 섞이면
「가장 싼 날을 찾아 드립니다」라는 약속이 깨진다.

**예상** — 1시간~1시간 30분. 창고 함수 · 창구 교체 · 화면은 그대로.

## §41 · 2026-09-09 검색 «기준을 다시 세움» — 대표님: *«다른 곳은 어떤 식으로 검색하는 거야? 디테일하게 정석적으로»*

### 실측 — 지금은 한글도 영어도 다 깨진다

| 손님이 친 것 | 지금 결과 |
|---|---|
| `그랜드 센트럴 호텔 상하이` | 정확히 일치한 곳이 **21번째** |
| 🔴 `그랜드센트럴` (붙여씀) | **0곳** |
| 🔴 `신라스테이` (붙여씀) | **0곳** |
| 🔴 `hilton danang` | 1등이 **발리** — 창고에 「힐튼 다낭」이 2곳이나 있는데도 |
| 🔴 `Grand Central Hotel Shanghai` | 1등이 **그랜드 시티텔 하노이** |

**자료는 충분하다** — 1,075곳 중 **1,024곳이 한글·영문 이름을 «둘 다» 갖고 있다.** 쓰지 못하고 있을 뿐이다.

### 다른 곳은 어떻게 하나 (조사)

**① 정확히 일치하면 가산점** — Traveloka 검색팀: <cite index="1-1">인기도에만 기대면 이름이 특이한 호텔은 아무리 정확히 쳐도 아래로 밀린다. 그래서 질의와 정확히 일치하는 항목에 가산점을 준다.</cite>

**② 한국어는 «세 가지 오타»를 따로 다뤄야 한다** — LBox 검색팀 정리:
<cite index="9-1">검색어 입력 오타(‘음쥬운전’→‘음주운전’), 한글을 영어로 입력(‘dmawndnswjs’→‘음주운전’), 띄어쓰기 오류. 세 가지를 각각 다른 방법으로 푼다.</cite>
🔴 **우리가 겪는 것이 정확히 세 번째(띄어쓰기)와 두 번째(한/영)다.**

**③ 초성 검색** — 한글은 <cite index="12-1">자모가 합쳐진 문자를 정규화로 초성·중성·종성으로 분해할 수 있다.</cite>
「ㅅㄹㅅㅌㅇ」로 「신라스테이」를 찾는 것은 한국 서비스의 «기본»이다.

### 우리 설계 — 4층으로 쌓는다

**1층 · 고르게 만들기(정규화)** — 비교 «전에» 양쪽을 같은 모양으로
```
유니코드 정규화 → 소문자 → 띄어쓰기·하이픈·점·쉼표·& 제거
「그랜드 센트럴 호텔 상하이」 → 「그랜드센트럴호텔상하이」
「Grand Central Hotel Shanghai」 → 「grandcentralhotelshanghai」
```

**2층 · 검색 열쇠를 «여러 벌» 미리 만들어 둔다** (호텔 하나마다)

| 열쇠 | 보기 | 무엇을 잡나 |
|---|---|---|
| 한글명 정규화 | 그랜드센트럴호텔상하이 | 붙여쓰기·띄어쓰기 |
| 영문명 정규화 | grandcentralhotelshanghai | 영어로 쳐도 |
| 한글 초성 | ㄱㄹㄷㅅㅌㄹ… | 「ㅅㄹㅅㅌㅇ」 |
| 한/영 자판 뒤바뀜 | rmfosem… | 「rmfosem」 |
| 도시·나라 (한/영) | 상하이 shanghai 중국 | 「shanghai」 |

🔴 **검색할 때 계산하지 않고 «미리» 만들어 둔다.** 매번 계산하면 느리다. 학습 일꾼이 매일 갱신한다.

**3층 · 점수** — 여러 열쇠 중 «가장 높은 점수»를 그 호텔의 점수로

| 등급 | 점수 |
|---|---|
| 완전히 같다 | **100** |
| 그 말로 시작 | 80 |
| 모든 말이 다 들어 있다 | 60 |
| 초성이 맞다 | 50 |
| 일부만 | 30 |
| 비슷하다(오타) | 10~25 |

🔴 **점수가 같을 때만** 후기 수 → 값을 본다.
🔴 **한글로 치든 영어로 치든 같은 점수판을 쓴다** — 어느 쪽이 1등이 되느냐가 달라지면 안 된다.

**4층 · 그래도 없으면** — 「혹시 이것을 찾으셨나요?」로 가장 가까운 것을 제안한다.

### 만드는 순서 (한 번에 다 넣지 않는다)

| 차수 | 무엇 | 이걸로 풀리는 것 | 시간 |
|---|---|---|---|
| **1차** | 1층 정규화 + 2층(한글명·영문명·도시) + 3층 점수 | 🔴 **위 실측 5가지가 전부 해결된다** | 1.5~2시간 |
| 2차 | 초성 · 한/영 자판 · 오타 교정 | 「ㅅㄹㅅㅌㅇ」·「rmfosem」·오타 | 별도 |

🔴 **1차를 먼저 확인한 뒤 2차를 넣는다.** 한꺼번에 넣으면 무엇이 틀렸는지 못 가린다.

💰 **돈은 들지 않는다** — 창고 안에서 끝난다. 외부 검색 서비스(Algolia·Elasticsearch)를 쓰지 않는다.
`pg_trgm`·`unaccent` 는 우리 창고에서 **켤 수 있다**(실측 확인).

🔴 **대상은 넓히지 않는다** — 우리가 소개한 호텔 + 신상만. 아고다 명부 전체(23,050곳)를 넣으면
값을 재지 않는 호텔이 섞여 「가장 싼 날을 찾아 드립니다」가 깨진다.

## §42 · 2026-09-09 검색 «속도» — 대표님: *«글자를 적으니깐 한참 뒤에 비슷한 글자가 밑에 뜬다»*

### 실측 — 최대 3.3초

| 친 것 | 걸린 시간(3회) |
|---|---|
| `그랜드` | 1.9s · 0.7s · 1.5s |
| 🔴 `그랜드 센트럴 호텔 상하이` | **2.9s · 3.3s · 2.4s** |
| `hilton` | 1.0s · 0.6s · 1.0s |

시트는 여기에 **타자 멈춤 350ms** 를 더 기다린다 → 손님은 **최대 3.6초**를 본다.
🔴 **자동완성의 세계 기준은 «100ms 안»이다.** 30배 느리다.

### 왜 느린가 — 넷

| # | 원인 |
|---|---|
| 1 | 🔴 **창고를 최대 6번 부른다** — 도시 목록 → 신상 → (없으면 넓혀서 다시) → 소개 → 값 → … 순서대로 기다린다 |
| 2 | 🔴 **`ilike '%말%'` 는 색인을 못 쓴다** — 앞에 `%` 가 붙으면 창고가 **1,075줄을 전부 훑는다** |
| 3 | 🔴 **`v_shop_card` 는 무거운 뷰다** — 값 계산(LATERAL·window)이 붙어 있다. 자가 점검도 이것 때문에 「확인 못 함」이 났다(§39) |
| 4 | 결과가 적으면 **조건을 넓혀 한 번 더** 부른다 — 느린 길을 두 번 간다 |

### 빠르게 하는 법 — 넷

**① 가벼운 «검색 전용 표»를 따로 둔다** (`shop_hotel_search`)
호텔 하나당 한 줄: `열쇠들 · 도시 · 성급 · 값 · 후기 수 · 사진`.
🔴 **무거운 뷰를 검색이 부르지 않게 한다.** 학습 일꾼(새벽 1:30)이 매일 갱신한다.

**② `pg_trgm` GIN 색인** — 이것이 있으면 `ilike '%말%'` 도 **색인을 탄다.**
전체 훑기(1,075줄)가 사라진다. 🔴 확장은 우리 창고에서 **켤 수 있다**(실측).

**③ 창고를 «한 번»만 부른다** — 점수 함수 하나가 정렬까지 끝내서 돌려준다. 6번 → **1번.**

**④ 같은 검색어는 저장해 둔다** — 창구 응답에 짧은 보관(예: 60초).
「그랜드」를 여러 손님이 치면 두 번째부터는 창고를 아예 안 부른다.

**목표: 100~200ms.** (지금 3.3초 → **15~30배**)

### 화면 쪽 (창구가 빨라진 뒤에 한다)

- 타자 멈춤 **350ms → 150ms** 로 줄인다 (창구가 빨라야 의미가 있다)
- 손님이 «기다린다»는 것을 알게 — 지금은 아무 표시가 없다
- 🔴 **늦게 온 옛 답이 새 답을 덮지 않게** — 이미 순번(`SHEET_SEQ`)을 넣어 두었다(§25)

🔴 **순서** — 속도(§42)를 «먼저» 만들고 그 위에 정확도(§41)를 얹는다.
검색 전용 표와 색인이 **정확도 설계의 «2층 열쇠»와 같은 것**이다 — 한 번에 같이 만든다.

### 무엇이 잘못돼 있었나 — 둘

**① 「10월」이라는 말을 아예 못 읽었다.** `parse()` 에 달을 뽑는 규칙이 없었다.
「10월」은 조건으로 빠지지 못하고 **찾을 이름(`rest`)** 으로 남아, 「10월」이 든 호텔을 찾다가 0곳 →
조건을 넓히는 길로 빠졌다. 그리고 값은 **언제나 가장 가까운 달(9월)** 을 썼다
(`shop_price_month` 에서 `order by ym limit 1`).

**② 넓힐 때 예산을 «통째로 풀었다».** 소개 숙소 쪽 조건이 `hi is null or n = 2 or …` 였다 —
`n = 2`(넓히는 회차)면 값 조건이 **사라졌다.** 그래서 「100,000원 이하」 딱지 밑에 **180,435원**이 앉았다.
🔴 **딱지와 목록이 다르면 손님은 속았다고 느낀다.** 신상 쪽은 1.3배로 넓히고 있었는데 소개 쪽만 달랐다.

## §47 · 2026-09-09 주말 날짜별 시트가 «보고 있는 달»로 열린다

> 대표님: *«11월인데 주말별을 클릭하면 9월로 표시되어 있어. 11월로 표시되어 바로 보게 되어야 된다»*

**왜 그랬나** — `openWeekend` 가 언제나 `months[0]`(가장 가까운 달)을 펼쳤다.
카드에는 11월 값이 적혀 있는데 시트는 9월을 펼치니, **손님이 방금 본 값이 시트 안 어디에도 없었다.**

**고친 것** — 카드가 이미 갖고 있는 `ym`(그 값이 어느 달 값인지)을 시트에 넘긴다.
`openWeekend(hid, name, ym)` → `drawMonth(months.includes(ym) ? ym : months[0])`.
🔴 검색 화면만이 아니라 **첫 화면·도시 화면·내 정보(찜) 전부** 같은 부품을 쓰므로 한 번에 고쳐졌다.
바꾼 곳: `public/shop.js`(부품 + 호출 2곳) · `public/index.html`(2곳) · `public/likes.html`(1곳).
