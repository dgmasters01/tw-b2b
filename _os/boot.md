# TW OS Boot Sheet

> **매 채팅 시작 시 Claude가 가장 먼저 읽는 1개 파일.**
> 이거 1개로 작업 90%가 가능하다. 깊이 필요 시에만 추가 fetch.

---

## 1. 헌법 1조 + OS 핵심 (5줄)

- **대표님은 결정만 한다. 시스템이 모든 실행과 검증을 한다.**
- 각 프로젝트는 완전 독립 (gohotelwinners / CEYLON / 호텔이야 별개).
- OS는 동일 운영 매뉴얼 + 봇 5종 + 메뉴 영역 표준만 공유.
- 틀(영역: DOCS / TOOLS / OS-CORE / SYSTEM)은 강제, 내용(메뉴)은 자유.
- 헌법 본문은 `OPERATIONS_CHARTER.md`, 200줄 이하 강제 (charter-length-bot 감시).

## 2. 11대 원칙 한 줄 요약 (11줄)

1. **단일 진실** — 모든 자산은 클라우드(GitHub + Vercel + Supabase)에.
2. **무인 실행** — 알림·배포·검증·리포트는 사람 없이 자동.
3. **어디서든 도달** — 핸드폰 한 대로 모든 작업 가능.
4. **전수 추적** — 누가/언제/왜/무엇을 영구 기록.
5. **무인 검증** — 검증 통과한 것만 보고. 실패는 자동 롤백·차단.
6. **AI 가독성** — 사람용 + AI용 이중 형식. 인덱스 + 분할 + 자동 갱신.
7. **상태 가시성** — 작업 상태 5초 내 파악 + 멈춘 위치 영구 저장.
8. **통합 관리** — 현황표 + 비즈니스 독스 + 갤러리 자동 동기화.
9. **가역성** — 모든 결정·작업 되돌릴 수 있음. 이중 백업.
10. **자기 강제** — 헌법은 시스템이 Claude에게 강제 (기억 의존 금지).
11. **메모리 사이클** — 토큰은 단계에 따라 충전·방전. 운영 모드 진입 시 비움.

## 3. 매 응답 의무 (헌법 부칙 16 강제)

**모든 응답 첫 5줄은 이 양식 그대로 (위반 시 헌법 위반):**

```
[작업 소요: 약 X분 / N단계 / 변경 파일: ...]   ← 부칙 12
🚦 ✅/⚠️ 한 줄                                  ← 부칙 13
📚 fetch 완료: boot.md / [작업파일] / 라이브 상태  ← 부칙 16 의무 2
🧭 북극성: ... / 🎯 한 채팅 한 결정: ...        ← 부칙 16 + 5-A
🔍 중복 점검 grep 결과: ...                     ← 부칙 16 의무 2
```

**묻는 것 = 정확히 4가지 (그 외는 자율 — 부칙 16 의무 3·4):**
① 비즈니스 방향 / ② 서비스 방향 / ③ 전체 틀 변화 / ④ 디자인 큰 방향(이미지 첨부)
→ 개발 순서·기술 선택·코드 구조·workflow는 절대 묻지 않음

🔴 **결정을 하나 확정했으면 그 자리에서 «묻지 않고» 문서 4곳을 갱신한다** (2026-08-12 대표님 지시):
```
① _business/decisions/YYYY-MM-DD-{주제}.md   전문 (왜 그렇게 정했는지 · 대표님 말씀 원문)
② DECISIONS_INDEX.md                        표 1행 + 하단 상세경로표 + 변경이력  (ID = 마지막+1 · 재사용 금지)
③ DECISIONS.md                              스토리 (언제/무엇을/왜/누가) — 상단에 추가
④ 숫자·표·서비스가 바뀌었으면 SYSTEM_MAP.md · ops.html 도 같이
```
**"정리할까요?" 라고 묻지 않는다.** 헌법 원칙 2(무인 실행)·8(통합 관리).
빠뜨리면 `decision-index-guard` 봇이 GitHub Issue 로 잡는다 (매일 KST 06시 + push 때).

**보고 형식 강제 (부칙 16 의무 5):**
무엇을 했나 / 어디 가서 / 무엇을 누르면 / 무엇이 보이는지 4줄 + 초등학생 언어 + 디자인은 이미지

### 🔑 창구 열쇠 (x-ops-token) — 클로드가 «모른다»고 하면 안 되는 것

🔴 **이 저장소는 Public 이다. 열쇠 값을 문서에 절대 적지 않는다.**
그래서 클로드는 새 창마다 스스로 찾아야 한다 — 대표님께 매번 여쭙지 않는다.

```
① 대표님이 주신 부팅 명령문 안에 있으면 그걸 쓴다
② 없으면 conversation_search("창구 열쇠 x-ops-token github-commit") 로 최근 대화에서 찾는다
   → 과거 대화 요약에 값이 남아 있다 (2026-08-29 이후 창들)
③ 그래도 없으면 그때만 대표님께 한 줄로 요청한다
```

⚠️ **옛 값이 대화에 함께 남아 있다.** 401 이 나오면 «열쇠가 없다» 가 아니라 «옛 값을 집었다» 이다.
가장 **최근** 대화의 값을 쓰고, 한 번 확인한 뒤 작업을 시작한다:
```
curl -s -o /dev/null -w "%{http_code}" \
  "https://gohotelwinners.com/api/ops/github-read?repo=tw-b2b&path=_os/boot.md" \
  -H "x-ops-token: <값>"      # 200 이면 정상, 401 이면 다른(더 최근) 값
```
스튜디오(gohotelwinners)와 블로그(staycurate) 는 **같은 값**을 쓴다.
