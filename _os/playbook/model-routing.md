# Playbook — 모델 라우팅 (어떤 작업에 어떤 모델을 쓰나)

> 2026-08-29 대표님 질문에서 시작: *"옵퍼스5하고 페이블5 중 이 정도 작업은 어떤 걸 사용해야 되나?
> 계속 지속적으로 작업해야 되는데 한도가 다 되면 기다려야 되잖아."*
> **한도는 유한한 자원이다. 시간·토큰과 같이 관리한다.** 부칙 13(채팅 라우팅) 옆에 붙는 룰북.

---

## 0. 왜 필요한가 (사실 근거)

| 사실 | 출처 |
|---|---|
| Fable 5 는 같은 일을 해도 한도를 **Opus 대비 약 2배 빠르게** 깎는다 | 앱 내 표시 |
| Max 요금제: Fable 은 주간 한도의 **50% 까지만** 무상. 넘으면 별도 크레딧 | Anthropic 도움말 «Fable 5 on your plan» |
| Pro 요금제: Fable 은 요금제 한도가 아니라 **선불 크레딧**으로 과금 | 위와 같음 |
| Fable 이 절반 한도에 걸려도 **Opus 5 는 남아 있다** → 기다리지 말고 모델을 바꾼다 | 위와 같음 |

**그래서 기본값은 Opus 5 다.** Fable 은 «막혔을 때 꺼내는 카드».

## 1. 표시 형식 (의무)

매 응답 두 번째 줄(🚦 라우팅) **뒤에 이어서** 한 조각 붙인다. 줄을 새로 만들지 않는다(부칙 16 5줄 유지).

```
🚦 ✅ 진행 가능 · 🧠 Opus 급 작업 (Fable 불필요)
🚦 ✅ 진행 가능 · 🧠 🔴 Fable 권장 — 되돌리기 어려운 구조 결정
🚦 ⚠️ 새 채팅 권장 · 🧠 다음 채팅은 Sonnet 이면 충분 (조회·보고)
```

지금 어떤 모델로 도는지 클로드는 모를 수도 있다. **«이 작업에 맞는 급»을 말하는 것이지, «지금 모델이 틀렸다»가 아니다.**

## 1-B. 🔴 마지막 줄 의무 — «다음 작업 = 어느 모델» 을 이름까지 말한다 (2026-08-29 대표님 지시)

> 대표님: *"다음에 버전을 네가 무슨 작업으로 진행해라고 같이 항상 이야기해 줘야 될 것 같애. 나는 모르잖아.
> 네가 가장 잘 아는 거니까. 버전도 이야기해 줘야 됨."*

**모든 응답의 마지막 줄**에 이 한 줄을 박는다. 급(Opus 급)이 아니라 **모델 이름과 버전을 그대로** 쓴다.

```
🧠 다음 작업 «P1 표 정의 뽑기» = **Claude Opus 5** 로 여세요 — 읽기만이라 Fable 불필요
🧠 다음 작업 «발행 창구 옮기기» = **Claude Fable 5** 로 여세요 — 되돌리기 어려운 구조 변경
🧠 다음 작업 «이번 주 현황 보고» = **Claude Sonnet 5** 로 충분합니다 — 한도 아끼세요
```

지킬 것:
- **모델 이름 전체**로 쓴다. «Opus», «4번» 같은 줄임말 금지. 대표님이 화면에서 그대로 고르실 수 있어야 한다
- **다음 작업 이름**을 같이 쓴다. 모델만 말하면 무엇에 쓰라는 건지 모른다
- **왜 그 모델인지 한 조각** 붙인다 (읽기만 / 구조 결정 / 대량 반복 …)
- 다음 작업이 없으면 «다음에 이어서 하실 것»을 제안하고 거기에 모델을 붙인다. **빈칸으로 두지 않는다**
- 이 줄은 §1 의 🚦 줄과 **별개**다. 🚦 줄 = 지금 이 작업의 급, 마지막 줄 = **다음 작업의 모델 지정**

## 2. 판단 기준 — 작업 종류로 정한다

| 작업 | 급 | 왜 |
|---|---|---|
| 문서 읽기 · DB 실측 · 규칙대로 고치기 · commit · 보고 | **Opus 5** | 난이도가 아니라 «절차를 안 빠뜨리는 것»이 관건. 대부분의 작업이 여기 |
| 화면·API 만들기 · 봇 붙이기 · 버그 1~2회에 잡히는 것 | **Opus 5** | 같음 |
| 단순 조회 · 현황 보고 · 문서 정리 · 번역 | **Sonnet 5** | 한도를 거의 안 깎는다. 아껴 둔 만큼 뒤에 쓴다 |
| 되돌리기 어려운 구조 결정 (열쇠·격리·창구·DB 설계) | 🔴 **Fable 5** | 2026-08-29 «열쇠를 아고다 번호로» 같은 단편 판단 사고를 막는다 |
| 여러 문서를 종합해야 답이 나오는 판단 | 🔴 **Fable 5** | 문서 10개 이상을 한 번에 물려서 봐야 할 때 |
| 며칠 막힌 버그 · 원인이 안 잡히는 것 | 🔴 **Fable 5** | 한 번에 뚫으면 오히려 한도가 절약된다 |
| 대량 반복 작업 (표 수십 개 · 파일 수십 개) | **Opus 5** | 길이 싸움이라 한도 소모가 크다. 비싼 모델로 하면 손해 |

## 3. 모델을 바꿔도 안 끊기게 (이미 갖춰져 있다)

맥락이 대화창이 아니라 GitHub 에 있다(헌법 원칙 10 · 기억 의존 금지). 그래서 갈아타는 값이 싸다.

```
Opus 로 진행  →  어려운 대목에서 Fable 새 채팅  →  boot.md 부팅해서 이어받음
              →  결정만 받아 문서에 박음  →  다시 Opus 로 실행
```
Fable 채팅은 **결정만** 받고 끝낸다. 실행(커밋·검증·반복)을 Fable 로 하면 한도가 두 배로 녹는다.

## 4. 한도가 걸렸을 때 (기다리지 않는다)

```
① 지금까지 한 것 commit + push  (안전 지점)
② 인계 명령문 박스 제공          (chat-routing.md §4)
③ 남은 모델로 새 채팅 — Fable 이 막혔으면 Opus, Opus 가 빡빡하면 Sonnet 으로 조회부터
```
**남은 한도·초기화 시각은 설정 → 사용량(Usage)** 에서 대표님이 직접 보실 수 있다. 클로드는 그 숫자를 못 본다 — 추측해서 말하지 않는다.

## 5. 클로드가 하지 않는 것

- 요금제를 추측해서 «Max 이시니까» 라고 말하지 않는다. 모르면 «요금제에 따라 다릅니다» 라고 적는다
- 한도가 아깝다고 **검증·백업·문서 갱신을 건너뛰지 않는다.** 아끼는 대상은 모델 급이지 절차가 아니다
- 이 표시 때문에 응답 줄 수를 늘리지 않는다 (🚦 줄 뒤에 붙인다). 단 **§1-B 마지막 줄은 예외 — 반드시 한 줄로 박는다**
- «알아서 고르세요» 라고 넘기지 않는다. **모르는 건 대표님이 아니라 판단할 근거가 없는 경우뿐이고, 근거는 클로드에게 있다**
